# Импорт справочника ФККО на сервер

**Для:** команда бэкенда (waste-complex-platform)  
**От:** команда клиента «Учёт отходов» (C# / WPF)  
**Дата:** 27.05.2026

---

## Проблема

Клиент загружает справочник ФККО **только с вашего API**:

```
GET http://178.57.217.79:8080/api/v1/core/waste-types
Authorization: Bearer <token>
```

**Сейчас сервер возвращает 3 записи** (демо-seed):

| id | code      | fkko_code           | hazard_class |
|----|-----------|---------------------|--------------|
| 1  | WT-SLUDGE | 4 12 110 01 11 4    | 4            |
| 2  | WT-OIL    | 4 06 200 03 51 3    | 3            |
| 3  | WT-CHEM   | 4 14 200 01 11 5    | 5            |

Проверено напрямую (без клиента): ответ `200 OK`, массив JSON из **3 элементов**.  
Клиент **ничего не обрезает** — показывает всё, что приходит с сервера.

При этом `GET /accounting/batches` отдаёт **4+ партий** — ограничение только у справочника `waste_types`.

---

## Что нужно сделать

1. **Импортировать полный ФККО** в таблицу видов отходов (`waste_types` или аналог).
2. После импорта `GET /core/waste-types` должен отдавать **~9000+ позиций** (не 3).
3. **Желательно:** разрешить роли `operator` **чтение** `GET /core/waste-types` (сейчас 403 — оператор вводит ФККО вручную при регистрации партии).
4. **Опционально:** пагинация и поиск (`?search=`, `?page=`, `?page_size=`), если записей много.

## Формат записи для нашего API

Поля, которые использует клиент (`WasteTypeDto`):

| Поле API       | Тип    | Пример                          | Описание                          |
|----------------|--------|---------------------------------|-----------------------------------|
| `id`           | int    | 1                               | Автоинкремент в БД                |
| `code`         | string | WT-SLUDGE                       | Внутренний код (можно из ФККО)    |
| `name`         | string | Шлам нефтедобычи                | Наименование вида отходов         |
| `fkko_code`    | string | 4 12 110 01 11 4                | **11-значный код ФККО** (с пробелами) |
| `hazard_class` | int    | 4                               | Класс опасности **1–5** (последняя цифра кода) |
| `description`  | string | (опционально)                   |                                   |

### Структура 11-значного кода ФККО

Пример: `4 12 110 01 11 4`

- Знаки 1–8: происхождение и состав
- Знаки 9–10: агрегатное состояние и физическая форма
- Знак 11: **класс опасности** (1 = I … 5 = V)

## Пример CSV для импорта (шаблон)

```csv
code;name;fkko_code;hazard_class;description
WT-SLUDGE;Шлам нефтедобычи;4 12 110 01 11 4;4;
WT-OIL;Отработанное масло;4 06 200 03 51 3;3;
WT-CHEM;Химические остатки;4 14 200 01 11 5;5;
```

Разделитель: `;` или `,`. Кодировка: **UTF-8**.

## Пример SQL (PostgreSQL, черновик)

```sql
-- После импорта CSV в staging-таблицу:
INSERT INTO waste_types (code, name, fkko_code, hazard_class, description)
SELECT code, name, fkko_code, hazard_class, COALESCE(description, '')
FROM fkko_import_staging
ON CONFLICT (fkko_code) DO UPDATE SET
  name = EXCLUDED.name,
  hazard_class = EXCLUDED.hazard_class;
```

*(Имена таблиц и constraint уточните под вашу схему.)*

## Проверка после импорта

```bash
# 1. Логин
curl -X POST http://178.57.217.79:8080/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"chief@eco.local","password":"chief123"}'

# 2. Справочник (подставить access_token)
curl http://178.57.217.79:8080/api/v1/core/waste-types \
  -H "Authorization: Bearer <TOKEN>"
```

Ожидаем: **тысячи записей**, не 3.

Клиент (вкладка «Справочник ФККО») подхватит данные автоматически после **«Обновить»** или перезапуска — **менять клиент не нужно**.
